# アーキテクチャ — 分断のない1つのデータジャーニー

```
 合成生データ (送金トランザクション, PIIなし)
        │
        ▼  ①  Lakeflow 宣言的パイプライン
   ┌──────────────┐   bronze(生) → silver(クレンジング+品質期待値) → gold(派生特徴量)
   │  gold_features│
   └──────┬───────┘
          │  ② Unity Catalog が全資産を統制（スキーマ/PIIマスク/権限/リネージ）
          ▼
   ④ クラシックML: 勾配ブースティング決定木
      + 加法的な理由コード（SHAP相当: logit = baseline + Σ寄与）
          │  各取引に fraud_score と reason_codes(JSON) と decision_policy を付与
          ▼
   ┌──────────────────┐   ③ Lakebase: Delta→低遅延Postgresへ synced
   │ scored_transactions│──────────────┐
   └──────────────────┘               │
          │                            │
   ⑥ Databricks Apps                   ⑤ Genie Room
   （アナリスト・コックピット）          （日本語で全体傾向を探索）
   ・レビューキュー(スコア降順)          ・「海外と国内で的中率は？」
   ・なぜ止めるべきか（理由コード）       ・「深夜に不正は偏る？」
   ・ブロック期待価値 EV（円）           ・「未判定のブロック候補は何件・いくら？」
   ・ブロック/承認 → 運用ストアに記録
   ・上部にビジネスKPI
```

## 接続点（審査で強調するポイント）
1. **Lakeflow → UC gold** が ML と運用サービングの**単一ソース**。分断がない。
2. **ML の出力（スコア＋理由コード）が Lakebase に同期**され、App がライブに読む＝夜間バッチ抽出をやめる。
3. **解釈性(SHAP) と 自然言語探索(Genie) の役割分担**：
   - 個票の「なぜ止めるか」= 理由コード（モデル） → App で提示
   - 全体の「なぜこの傾向か」= 集計・セグメント（Genie） → 運用改善へ
4. **属人化の解消**：しきい値ポリシーで 97.7% を機械的に確定、残りだけ人が**理由コード＋EV**を見て判断→運用ストアに監査可能な形で記録。

## 意思決定支援の核: 期待金額価値 (EV)
```
EV(ブロック) = fraud_score × 送金額  −  (1 − fraud_score) × 誤検知コスト
```
モデルの確率・金額・誤検知コストを**1つの円換算指標**に統合。EV>0 なら「止める方が経済的に得」。
属人的な勘ではなく、**説明可能で一貫した判断基準**をアナリストに与える。

## なぜクラシックMLか
- 不正検知は表形式・大量ラベルの典型で、勾配ブースティングが高精度かつ高速。
- **加法的寄与（SHAP/木経路寄与）で厳密に説明可能**（`baseline + Σ寄与 = logit`、検算誤差 ~1e-15）。
- 規制対応・監査で「なぜ止めたか」を機械的に示せる＝金融の要件に直結。
