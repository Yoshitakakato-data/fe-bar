不正送金レビュー支援 — Databricks 実行手順

金融 / クラシックML × Databricks — エンドツーエンド・データジャーニー

ローカル版（src/, numpyのみ）と 1:1 対応する Databricks ネイティブ版 （databricks/, app/）の配備手順。列名・しきい値・コスト前提を ローカルと一致させてあるため、ローカルで得た数値がそのまま Databricks 上で再現できます。

0前提

Unity Catalog 有効ワークスペース ／ Serverless SQL Warehouse ／ MLflow・Model Serving ／ Lakebase が利用可能であること。 すべて合成データを使用し、実顧客データ・PII は使用しません。

B実行順

#実行するものコンポーネント補足
1databricks/02_unity_catalog_setup.sql の上半分（CREATE CATALOG/SCHEMA/VOLUME＋mask関数＋GRANT）Unity CatalogSQLエディタで実行。GRANT先グループ（fraud_analysts等）が無ければ該当行は調整/スキップ
2data/raw_transactions.csv を手順1で作成した Volume にアップロード—/Volumes/fraud_demo/fraud/raw/ へ
3databricks/01_lakeflow_ingest.py を Lakeflow パイプラインのソースに指定して実行Lakeflowターゲットを fraud_demo.fraud に設定。bronze/silver/gold_features が生成される
4databricks/03_train_model.py をノートブック実行クラシックMLGBDT学習＋SHAP理由コード → MLflow(UC)登録 → scored_transactions テーブル書き出し
502_unity_catalog_setup.sql の ALTER TABLE … SET MASK 行を実行Unity Catalog★scored_transactions 生成後（=手順4の後）に実行。PIIマスク付与
6databricks/04_lakebase_sync.md の手順（Lakebase インスタンス作成 → synced table → review_decisions テーブル）LakebaseDelta→Postgres 同期＋判断の書き込み先を用意
7databricks/05_genie_space_setup.md の手順（Genie Space 作成＋サンプル質問6問登録）Genie Room対象テーブル＝scored_transactions
8app/ を databricks apps deploy fraud-review --source-code-path .Databricks Appsapp.yaml に Lakebase 接続情報を注入。app.py(Flask) が起動
つまずきやすい2点（意図的に順序依存）
  • 手順5のマスク付与は手順4の後。 scored_transactions が存在してから ALTER TABLE … SET MASK を実行（1回で全部流すとテーブル未作成でエラー）。
  • 手順3は通常の「Run」ではなく Lakeflow（旧DLT）パイプラインとして作成し、01_lakeflow_ingest.py をソース指定して起動する。
最短で「動く」を確認するなら 手順 1 → 3 → 4 まで（Lakeflow取込 → gold → ML → スコア＋理由コード）で中核が通り、 SELECT * FROM fraud_demo.fraud.scored_transactions が実行証跡になります。その後 6→7→8 で運用・探索・公開層を追加。
